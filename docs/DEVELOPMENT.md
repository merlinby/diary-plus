# Документация разработчика

## Архитектура

Приложение — Android-оболочка сайта diary.e-schools.by на Java без AndroidX и Gradle. JavaScript-модули в assets выполняют локальную аналитику и подстановку учётных данных.

| Компонент | Назначение |
| --- | --- |
| `MainActivity` | WebView, меню, загрузки, выбор вложений, профили и работа с паролями |
| `StudentTwoActivity` | Наследует MainActivity и запускается в отдельном процессе `:student2` |
| `DiaryApplication` | Задаёт `WebView.setDataDirectorySuffix("student2")` второму процессу до обращения к WebView; первый профиль использует стандартный каталог |
| `LauncherActivity` | Открывает последний выбранный профиль |
| `ProfileStore` | Атомарно сохраняет имена, логины, выбранный профиль и зашифрованные записи; не хранит открытых паролей |
| `CredentialsVault` / `PasswordCipher` | Шифрование паролей через Android Keystore и AES-256-GCM со случайным IV и AAD из номера профиля и логина |
| `analytics.js` | Получение данных ученика или родителя, выбор ребёнка и периода, расчёт средних отметок |
| `login.js` | Распознавание формы и подстановка данных с проверкой HTTPS-origin и совпадения логина, без отправки формы |

Пакет приложения — `by.local.diaryplus`. Требования к окружению, команды тестирования и сборки приведены в [README](../README.md).

## Профили и доступ к паролям

Сессии двух профилей хранятся независимо. Первый профиль должен использовать стандартный каталог WebView, второй — каталог с суффиксом `student2`.

Открытие приложения, возврат из фона и переключение уже авторизованных профилей не требуют разблокировки приложения. Системное подтверждение используется только при получении, сохранении или редактировании сохранённого пароля. Ключ Android Keystore требует системной аутентификации за последние 30 секунд.

Для автоподстановки сначала проверяется наличие формы входа с пустым паролем. Сохранённый пароль извлекается только при необходимости и только для соответствующего логина на `https://diary.e-schools.by`. Запрос подтверждения также используется при открытии настроек сохранённого пароля. Пока приложение активно, форма проверяется раз в секунду, в том числе после динамического перехода на страницу входа. В фоне и при открытых настройках входа проверка приостанавливается. Отмена подтверждения или ошибка хранилища останавливает автоматические попытки до следующей загрузки страницы. «Сохранить» только записывает настройки и откладывает подстановку до следующей загрузки страницы; «Отмена» закрывает диалог без записи.

## Проверки на устройстве

В версии 0.3.3 пользователь проверил автоподстановку сохранённых данных на телефоне и подтвердил ожидаемое поведение. Это не заменяет остальные проверки ниже.

Для версии 0.3.3 остаются незавершёнными следующие проверки:

1. Обновление поверх установленного приложения с сохранением обоих профилей и паролей.
2. Возврат из фона через минуту и переключение авторизованных профилей без запроса отпечатка.
3. Истёкшая или очищенная сессия: подтверждение доступа к паролю, подстановка и ручное нажатие «Войти».
4. Отмена биометрии: дневник остаётся открыт, автоматический запрос не зацикливается.
5. Android 10: подтверждение кодом устройства; Android 11+: BiometricPrompt.
6. Удаление блокировки устройства или инвалидация ключа: повторное сохранение пароля без потери второго профиля.
7. «Ещё → Проверить обновления»: новая версия открывает скачивание APK в браузере; текущая версия и ошибка сети показывают сообщения. Отмена проверки или уход в фон не должны открывать браузер после завершения запроса.

JS- и JVM-тесты не подтверждают работу WebView, Keystore, биометрии и реальных сессий на Android. Проверки сборки включают компиляцию для API 35, наличие DEX и ресурсов, проверку подписи через apksigner и выравнивания через zipalign.

## Технические ограничения

- Для SPA-формы входа используется периодическая проверка через `evaluateJavascript`, без JavaScript bridge. Появление формы, подтверждение доступа и отсутствие повторных запросов после отмены нужно дополнительно проверить в Android WebView.
- Операции Keystore и файлового хранилища выполняются в UI-потоке. Возможность их переноса в фон требует проверки.
- Автоподстановка и даты уроков основаны на восстановленном API-контракте, без официальной спецификации.
- Границы четвертей ориентировочные и редактируются пользователем. При неизвестной дате урока учитывается вся неделя с предупреждением.
- Среднее арифметическое рассчитывается без весов и правил итоговых отметок. Цветовая шкала рассчитана на 10-балльную систему.

## Подпись и секреты

Ключ подписи APK и его пароль хранятся отдельно от Git. Для сборки используются `signing/release.jks` и `signing/password.txt` либо каталог из `DIARY_SIGNING_DIR`. Обновления должны сохранять исходную подпись приложения.

Ключ Android Keystore для пользовательских паролей создаётся на телефоне и не связан с ключом подписи APK.

В тестах допустимы только вымышленные данные. Ключи, пароли, cookies, токены, реальные ответы дневника и содержащие их журналы не должны попадать в репозиторий.
