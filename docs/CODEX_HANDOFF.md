# Передача проекта в Codex

Актуальный исходный код: 0.3.1, versionCode 5, пакет by.local.diaryplus. Работа велась 25 октября 2026. Пользователь проверяет APK на Samsung Galaxy S21, Android 15. Общение на русском.

## Что сделано

Приложение — неофициальная Android-оболочка официального сайта diary.e-schools.by, написанная на Java без AndroidX/Gradle. JS-модули в assets показывают локальную аналитику и подставляют учётные данные.

- MainActivity: WebView, меню, загрузки/выбор вложений, профили, биометрия.
- StudentTwoActivity: наследует MainActivity, запускается в процессе :student2.
- DiaryApplication: задаёт WebView.setDataDirectorySuffix("student2") только второму процессу до любых обращений к WebView. У первого профиля остаётся исходный каталог для сохранения ранее созданного входа.
- LauncherActivity: открывает последний выбранный профиль.
- ProfileStore: атомарно сохраняет имена, логины, последний профиль и зашифрованные записи. В нём нет открытых паролей.
- CredentialsVault/PasswordCipher: AES-256-GCM, случайный IV, AAD из номера профиля и логина. Ключ Android Keystore требует системной аутентификации за последние 30 секунд.
- analytics.js: профиль ученика/родителя, список детей, четверти/даты/год, недельные запросы к дневнику и средние отметки.
- login.js: распознавание формы, автоподстановка без отправки, проверка точного origin и совпадения логина.

## Последняя правка — критически важное пожелание

В 0.3.0 приложение требовало отпечаток при каждом возврате из фона. Пользователь считает это избыточным. В 0.3.1 блокировка всего приложения удалена. Сначала проверяется наличие реальной формы входа с пустым паролем; только тогда извлекается сохранённый пароль и при необходимости вызывается системная проверка. Уже авторизованный дневник и переключение авторизованных профилей не должны запрашивать отпечаток. Запрос при открытии настроек сохранённого пароля остаётся.

## Что известно о тестировании

Пройдены JS-тесты в jsdom, JVM-тесты хранилища метаданных и AES-GCM, компиляция Android API 35, проверка DEX/ресурсов, подписи apksigner и zipalign. APK 0.3.1 подписан тем же ключом, что все предыдущие сборки.

Авторизация, системная биометрия/Keystore и жизненный цикл на реальном Android не проверялись агентом. Пользователь сообщил, что нашёл сохранение пароля, и подтвердил запрос отпечатка при возврате в 0.3.0. Результата проверки 0.3.1 пока нет.

## Что проверить дальше

1. Поставить 0.3.1 поверх старой версии: сохранить оба профиля и пароли.
2. Свернуть/вернуться через минуту, переключить уже вошедшие профили: без отпечатка.
3. Истёкшая/очищенная сессия: запрос только для пароля, затем подстановка и ручное нажатие «Войти».
4. Отмена биометрии: дневник остаётся открыт, автоматический запрос не зацикливается.
5. Android 10 fallback через код блокировки и Android 11+ BiometricPrompt.
6. Удаление блокировки телефона/инвалидация ключа: восстановление через повторное сохранение, отсутствие потери второго профиля.
7. SPA-форма входа, появившаяся после полной загрузки страницы: JS наблюдатель подставляет уже доступные значения, но нативный доступ к зашифрованному паролю запускается onPageFinished/onResume. Это потенциальный пробел: для полностью динамического разлогинивания может понадобиться дополнительный сигнал/проверка, без открытия небезопасного JS bridge.
8. Проверить возможность неблокирующего чтения Keystore/файлов: сейчас операции выполняются в UI-потоке.
9. Автоподстановка/даты уроков основаны на восстановленном API-контракте, не на официальной спецификации.

## Аналитика: ограничения

Четверти имеют ориентировочные календарные границы; даты редактируются. Если дата урока неизвестна, учитывается вся неделя с предупреждением. Среднее простое, без весов и правил итоговых отметок. Цвета для 10-балльной шкалы.

## Подпись и секреты

Ключ установленного приложения НЕ находится в Git. Отдельный приватный архив содержит signing/release.jks и signing/password.txt. Верните их в локальный каталог signing/ перед сборкой либо задайте DIARY_SIGNING_DIR. Ключ пользователя для паролей создаётся на самом телефоне и не связан с ключом подписи APK.

В Git нет реальных учётных записей, паролей учащихся, cookies или токенов. Примеры в тестах вымышленные. Репозиторий пока локальный: origin и удалённый GitHub-проект не созданы.
